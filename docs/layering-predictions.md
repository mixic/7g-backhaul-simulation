# Layering predictions (frozen)

**Status:** FROZEN. This file is committed before any experiment code in this
testbed and is not edited afterwards. Corrections, if any, go in a dated
addendum at the end; the predictions and tolerances themselves stay fixed. The
freeze commit hash is recorded in [`layering-results.md`](layering-results.md).

**Measurement note:** the only measured calibration value in this document is
the zlib compression ratio of the synthetic corpus. Every overhead, MTU, loss
probability, seed count and payload size is **stipulated** and is labelled as
such. A stipulated value is not a measurement of a deployed network.

**Scope note:** this testbed measures size, delivery, ordering and
authentication-acceptance behaviour. It does **not** evaluate cryptographic
security. The AEAD is a toy construction whose key is published in the source.

## 1. Notation

`A -> B` means layer `A` is applied first on the sender, so `A` is innermost
and `B` is outermost on the wire. The receiver applies the partial inverses in
reverse order.

| Layer | Meaning | Overhead | Size effect | Structural fields |
|---|---|---:|---|---|
| `C` | zlib compression, level 6 | 0 declared | data-dependent (zlib framing) | none |
| `E` | toy AEAD, 12-byte nonce + 16-byte tag | 28 B stipulated | fixed | none |
| `T` | IP-in-UDP tunnel header | 28 B stipulated | fixed | `udp_len` |
| `F` | fragmentation to path MTU | 8 B per fragment stipulated | fixed per fragment | `offset`, `length` |
| `S` | RFMP v0.1 sequence header | 24 B stipulated | fixed | none |
| `R` | middlebox rewrite (not a sender layer) | 0 | none (length preserving) | target-dependent |

The RFMP header is 24 bytes by the v0.1 specification. The 28-byte `T` and
`E` overheads, the 8-byte fragment header, the 1500-byte path MTU, the 0.1
per-fragment loss probability and the 16-byte tag are all **stipulated**.

## 2. Observable set O (fixed before any experiment)

1. wire bytes per datagram;
2. maximum application payload for a given path MTU;
3. datagram delivery probability under stipulated i.i.d. fragment loss;
4. in-order delivery fraction;
5. duplicates delivered to the application;
6. authentication acceptance rate.

Header visibility at a middlebox is recorded as a **separate column**. It is
not part of O and a visibility difference alone never refutes a prediction.

Where a prediction does not vary with loss, in-order delivery is 100 % and
duplicates are 0 % by construction (single path, no retransmission). Those
values are recorded but are not the discriminating observables.

## 3. Formal survival condition (the research claim)

For target field `f` introduced by layer index `i` in a stack
`L0 -> ... -> L(n-1)`:

```text
visible(f)        = no L_j with j > i has kind E or C
reachable(f, d)   = n - i <= d          # d = middlebox parser depth
authenticated(f)  = f is in an E layer's AAD scope
structural(f)     = f is length- or offset-bearing

mutated           = reachable(f, d) and visible(f)
auth_ok           = not (mutated and authenticated(f))
delivered         = auth_ok and not (mutated and structural(f))
```

The middlebox rewrite is applied if and only if `mutated`. A visible,
authenticated field that is rewritten must fail authentication. A visible,
unauthenticated, structural field that is rewritten must break delivery. An
invisible or unreachable field must not be rewritten, even when a parser would
otherwise accept it.

### Corpus calibration (measured)

The synthetic corpus is generated by the code in
`simulation/layering/scenarios.py` (LCG over consonant/vowel syllables). Its
zlib level-6 ratios, measured before freezing with Python 3.14.7 / zlib 1.3.1,
are:

| Corpus | Bytes | zlib bytes | Ratio |
|---|---:|---:|---:|
| text | 32768 | 17225 | 0.5257 |
| text | 8192 | 4395 | 0.5365 |
| text | 1000 | 570 | 0.5700 |
| random | 32768 | 32786 | 1.0006 |

The random corpus is a SHAKE-256 stream. These ratios are measured; they
define the scenario and do not depend on any prediction outcome.

## 5. Predictions

The numbers below are deterministic consequences of the layer table and the
stipulated scenario; they are frozen before running. The percent tolerances
for stochastic quantities were chosen from the binomial standard error at the
stipulated seed counts (≈1.1 pp for 2000 model seeds, ≈0.8 pp for 4000 Linux
datagrams), rounded up to cover implementation differences, not fitted to
observed results.

### P1 — Compression and encryption do not commute on size (regression)

**Stacks:** `C -> E` versus `E -> C`. **Payload:** 32768-byte text corpus, and
separately 32768 random bytes. **MTU:** 1500 (no fragmentation).

**Predicted, text:** `C -> E` = 17253 B, `E -> C` = 32815 B.

- `E -> C` wire bytes must be **at least 1.75×** `C -> E` (measured calibration
  gives 1.902×), and the difference must be at least **60 %** of `C -> E`.
- Maximum payload at MTU 1500: `C -> E` = 2670 B, `E -> C` = 1461 B. The
  compressible ordering must be **at least 1.5×** larger and at least
  **1000 B** larger.

**Predicted, random:** `C -> E` = 32814 B, `E -> C` = 32815 B. The absolute
difference must be **at most 64 B** (zlib framing only).

**Refuted if** any threshold above is missed in the executable model or SimPy.
Linux checks the wire-byte claims only (see §6); its text ratio threshold is
relaxed to **1.5×** because the Linux input begins with a 28-byte IP/UDP
header in place of 28 bytes of text.

### P2 — Fragmentation and encryption differ in overhead but not delivery (regression)

**Stacks:** `E -> F` versus `F -> E`. **Payload:** 12000 random bytes.
**MTU:** 1500. **Fragments:** 9 in both orderings. **Loss:** `p = 0.1`,
i.i.d. per fragment; 2000 paired seeds.

**Predicted bytes:** `E -> F` = 12100 B, `F -> E` = 12324 B. The difference
must be **exactly 224 B = 28 × (9 − 1)**, zero tolerance.

**Predicted delivery:** both `(1 − 0.1)^9 = 0.38742`.

- Model/SimPy: each estimate within **2.5 pp** of 0.38742, and the paired
  difference within **2.0 pp** of zero.
- Linux: each estimate within **4.0 pp** of 0.38742, and the paired difference
  within **4.0 pp** of zero.

**Refuted if** the byte difference is not exactly 224 B, or any delivery
tolerance is missed.

### P3 — Header rewriting commutes with integrity protection only outside the authenticated scope (research)

**Payload:** 1200 random bytes. **No loss.** Three cases:

| Case | Stack | AAD scope | Rewrite target | Predicted visibility | Predicted mutation | Predicted auth acceptance | Predicted delivery |
|---|---|---|---|---|---:|---:|---:|
| a | `E -> T` | `T.src_port` | `T.src_port` | visible | yes | **0 %** | 0 % |
| b | `E -> T` | none | `T.src_port` | visible | yes | **100 %** | 100 % |
| c | `T -> E` | none | `T.src_port` | invisible | no | **100 %** | 100 % |

Acceptance must be exactly 0 % or 100 % in every run; no intermediate value
is permitted. Case (c) must also report `mutation = false` and
`visibility = false`.

**Refuted if** any fidelity yields an acceptance rate other than the predicted
extreme, or case (c) reports a mutation.

### P4 — Fixed-overhead layers commute on size (regression)

**Stacks:** all six orderings of `T`, `E`, `S`. **Payload:** 1024 random
bytes. **No loss.**

- Wire bytes must be identical across all six orderings: **1104 B**
  (1024 + 28 + 28 + 24), zero tolerance.
- Maximum payload at MTU 1500 must be identical: **1420 B**, zero tolerance.
- Delivery and authentication acceptance must be 100 % for every ordering.
- Header visibility is recorded per ordering as a separate column (for
  example `S.seq` is invisible when `S` is applied before `E`). A visibility
  difference is **not** a failure.

**Refuted if** any ordering differs in wire bytes, maximum payload, delivery
or authentication acceptance.

### P5 — Compress-then-fragment beats fragment-then-compress on delivery (regression)

**Stacks:** `C -> F` versus `F -> C`. **Payload:** 8192 text bytes.
**MTU:** 1500. **Loss:** `p = 0.1`, i.i.d. per fragment; 2000 paired seeds.

**Predicted fragment counts:** `n1 = 3` for `C -> F`, `n2 = 6` for `F -> C`
(per-fragment compression has less context and `n2 > n1`).

**Predicted delivery:** `0.9^3 = 0.729` versus `0.9^6 = 0.531441`; the
difference must be **19.7559 pp**.

- Model/SimPy: measured difference within **3.0 pp** of 19.7559 pp; each
  estimate within **3.0 pp** of its formula.
- Linux: measured difference within **4.0 pp** of 19.7559 pp; each estimate
  within **4.0 pp** of its formula.

**Control case:** 1000 text bytes gives `n1 = n2 = 1` and predicted delivery
`0.9` for both. The paired difference must be within **1.0 pp** of zero in the
model/SimPy and **3.0 pp** of zero in Linux.

**Refuted if** the difference or either estimate falls outside the tolerance,
or the control case shows a significant difference.

### P6 — The visibility/reachability/integrity condition holds over a sweep (research, core)

**Cases:** all six orderings of `T`, `E`, `S`; target `T.src_port` or
`S.seq`; middlebox parser depth `d ∈ {1, 2, 3}`; AAD scope either none or the
target (the protected variant is only valid when the target is visible) — **54
cases**. **Payload:** 1024 random bytes. **No loss.**

For each case, §3 predicts `visible`, `mutation`, `auth_ok` and `delivered`.
Authentication acceptance is exactly 100 % or 0 %; the rewrite is applied
exactly when `reachable and visible`.

**Tolerance:** zero. Every one of the 54 cases must match on all four
columns in every fidelity.

**Refuted if** any case disagrees on visibility, mutation, acceptance or
delivery. The list of disagreeing cases is reported, not removed.

### P7 — Integrity exclusion is not sufficient: structural fields break delivery (research, core)

**Stack:** `T -> F`. **Payload:** 4096 random bytes (3 fragments), no loss.
All three cases are visible and unauthenticated, so the integrity-scope rule
alone predicts survival.

| Case | Rewrite target | Predicted auth acceptance | Predicted delivery |
|---|---|---|---:|---:|
| a | `F.length` → `0x0009` | 100 % | **0 %** |
| b | `T.udp_len` → `0x0009` | 100 % | **0 %** |
| c | `T.src_port` → `0x9C40` (inert) | 100 % | **100 %** |

**Tolerance:** zero.

**Refuted if** either structural rewrite delivers a datagram, or the inert
rewrite fails to deliver one, in any fidelity.

## 6. Experimental protocol

The executable-model and SimPy runs use seeds `1 … 2000` and the same
deterministic loss draws (`loss_unit(seed, datagram, fragment)`), so the two
orderings in P2 and the `C -> F` / `F -> C` pair in P5 are paired. Linux
pairs on the `tc netem` seed: one run uses seed `r` for both orderings, with
100 datagrams per run and 40 runs.

Linux normalisation: the application payload is set to
`model_payload − 28` bytes so that the IP/UDP datagram handed to the layer
codec is exactly the model's payload size. The 28-byte inner IP/UDP header
therefore occupies the first 28 payload bytes; this is why P1's text ratio
threshold is relaxed for Linux. TUN and veth MTUs are 40000 B so that only
the modelled `F` layer fragments; the modelled path MTU stays 1500 B.

Commands (run after this file's commit):

```powershell
py -3 -m validation.layering.run_model  --output validation\layering\results\model_observations.csv
py -3 -m validation.layering.run_simpy  --output validation\layering\results\simpy_observations.csv
py -3 -m validation.layering.run_linux  --output validation\layering\results\linux_observations.csv
py -3 -m validation.layering.report --model validation\layering\results\model_observations.csv --simpy validation\layering\results\simpy_observations.csv --linux validation\layering\results\linux_observations.csv --verdicts validation\layering\results\verdicts.csv --doc docs\layering-results.md
```

Linux requires root inside a container or WSL2 (network namespaces, veth,
TUN and `tc netem`). The exact commands and privilege list are in
[`validation/linux_layering/README.md`](../validation/linux_layering/README.md).

## 7. Interpretation limits (fixed in advance)

- Security properties, including the information leakage of
  compress-then-encrypt, are not evaluated.
- Loss is i.i.d. and stipulated; there is no wireless PHY/MAC model and no
  congestion control.
- Results hold for the stipulated overheads, corpora and middlebox model. The
  middlebox is a user-space rewriter with a fixed parser depth, not a measured
  middlebox.
- P1, P2, P4 and P5 are arithmetic regression tests. Confirming them shows
  that the implementations do the specified arithmetic; it is not evidence
  about deployed networks.
- P3, P6 and P7 are the research contributions. P3 case (a) corresponds to the
  known operational failure of NAT-style rewriting against IPsec
  authentication (for example RFC 3715 and the middlebox measurements of Honda
  et al.); the testbed does not reproduce real ESP or a real NAT.
- The three fidelities share the same codec. Agreement across them checks the
  codec under different execution environments (event scheduling, kernel
  loss), not independent protocol semantics.

## 8. Addenda

### 2026-11-03 — cross-fidelity P5 fragment count and zlib variant

This addendum does not alter any prediction, tolerance or refutation condition.

The frozen P5 prediction fixes `n1 = 3` for `C -> F` at 8192 text bytes. That
value was measured with the executable model on Python 3.14.7, whose zlib
reports `1.3.1.zlib-ng`. The Linux fidelity uses stock zlib 1.3.1 and, by the
normalisation in §6, feeds the 28-byte IPv4/UDP header through `C`. Under those
conditions `C -> F` has `n1 = 4`, so the frozen 19.7559 pp difference is not the
Linux scenario. Linux measures 11.10 pp, consistent with
`0.9^4 − 0.9^6 = 12.47 pp`.

P5 is therefore reported as **refuted at the Linux fidelity** in
[`layering-results.md`](layering-results.md). The prediction is not edited and
no tolerance is changed. The discrepancy is a scenario/normalisation mismatch,
not a failure of the `(1−p)^n` arithmetic.

The compression ratios in §4 were measured with zlib-ng; stock zlib compresses
the same corpora slightly differently (for example 17383 versus 17225 bytes for
the 32768-byte text corpus). This does not affect P2, P4, P6 or P7, but it is
recorded for reproducibility.
